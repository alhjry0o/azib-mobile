# COST_SHARING — محرك تقسيم تكاليف العرس الجماعي

> أُنشئ في **P10** تنفيذاً لبند الاكتمال في HRD.
> **عام المستودع:** لا أسرار، لا بيانات شخصية حقيقية.
> **قاعدة حاكمة:** الميزانية **للحساب والاتفاق فقط**. لا أموال داخل التطبيق، لا محفظة، لا Escrow (ADR-0005).

آخر تحديث: 2026-11-16 (إغلاق P10).

## 1) الضمانات غير القابلة للتفاوض

| # | الضمان | موضع enforcement |
|---|--------|------------------|
| 1 | المحرك **دالة نقية** بلا React وبلا IO وبلا ساعة | `engine/cost-sharing.ts` · `engine/largest-remainder.ts` |
| 2 | **أعداد صحيحة فقط** بالريال — لا كسور عشرية تُقارن | حساب `floor(num/den)` ثم `num % den` |

## 2) الصيغ الثلاث

| النمط | المدخل | التوزيع |
|-------|--------|---------|
| **Equal** | لا أوزان | وزن 1 لكل عضو نشط |
| **Weighted** | `weights: {memberId, weight}[]` | وزن صحيح موجب لكل عضو؛ ناقص/صفر ⇒ `INVALID_WEIGHT` |
| **Custom** | `customShares: {memberId, amount}[]` | مبالغ صريحة؛ المجموع ≠ المشترك ⇒ `CUSTOM_SUM_MISMATCH` |

**Individual + Shared:** كل بند إما `shared` (يُوزَّع بالنمط) أو `individual` (يُنسب لصاحبه وحده). حصة العضو = `individual + shared`.

## 3) Largest Remainder — الخوارزمية

```
لكل عضو:  numerator = total × weight
          base      = floor(numerator / weightSum)
          remainder = numerator % weightSum
leftover = total − Σ base
يُمنح +1 لأصحاب أكبر البواقي، بالتنازل حتى ينتهي leftover
كسر التعادل: ترتيب الأعضاء المعلن (index تصاعدي) — مستقر ومُختبَر
```

**لا مقارنة كسور عشرية إطلاقاً:** الترتيب يجري على `numerator % weightSum` وهو عدد صحيح.

### 3.1 أمثلة محسوبة (مُغطّاة باختبارات)

| الحالة | المدخل | الناتج | المجموع |
|--------|--------|--------|---------|
| Equal | 100000 ÷ 3 | **33334 · 33333 · 33333** | 100000 |
| Equal | 10 ÷ 4 | **3 · 3 · 2 · 2** | 10 |
| Equal | 7 ÷ 3 | **3 · 2 · 2** | 7 |
| Weighted | 100000 بأوزان 1:2:3 | **16667 · 33333 · 50000** | 100000 |
| Custom | 60000 + 40000 مقابل مشترك 100000 | **60000 · 40000** | 100000 |
| Custom غير متساوٍ | 40000 + 40000 مقابل 100000 | **رفض `CUSTOM_SUM_MISMATCH`** | — |
| Individual + Shared | فردي 20000 لـA + مشترك 90000 ÷ 3 | **A 50000 · B 30000 · C 30000** | 110000 |
| مختلط | مشترك 100001 ÷ 3 + فردي 33333 لـB | **A 33334 · B 66667 · C 33333** | 133334 |
| عضو واحد | 12345 | **12345** | 12345 |
| إجمالي صفر | 0 ÷ 3 | **0 · 0 · 0** | 0 |
| انسحاب C | Equal 100000 بعد خروج C | **50000 · 50000** | 100000 |

**تفكيك مثال الأوزان:** `100000×1 = 100000`، `%6 = 4`؛ `200000 %6 = 2`؛ `300000 %6 = 0`. الأساسات `16666+33333+50000 = 99999`، الباقي 1 ⇒ صاحب أكبر باقٍ (الأول) ⇒ 16667.

## 4) الرفض والحالات الحدّية

| الكود | السبب |
|-------|-------|
| `INVALID_TOTAL` | إجمالي غير صحيح/سالب/غير منتهٍ |
| `NO_MEMBERS` | لا أعضاء نشطين |
| `DUPLICATE_MEMBER` | تكرار معرّف عضو |
| `INVALID_WEIGHT` | وزن غير صحيح أو ≤ 0 |
| `INVALID_AMOUNT` | مبلغ بند غير صحيح أو سالب |
| `UNKNOWN_MEMBER` | بند فردي منسوب لعضو غير موجود/غير نشط |
| `INVALID_CUSTOM_SHARE` | حصة مخصصة غير صحيحة |
| `CUSTOM_SUM_MISMATCH` | مجموع الحصص ≠ إجمالي المشترك |

**مفتاح ترجمة ناقص:** `budget.errors.INVALID_TOTAL` غير موجود في `weddings.json` ⇒ يُعرض المفتاح الخام عند هذا الخطأ تحديداً. بند مفتوح في `PROJECT_CONTEXT §8`.

## 5) أثر الانسحاب وإضافة عضو

`computeWithdrawalImpact` دالة نقية تُعيد:

| الحقل | المعنى |
|-------|--------|
| `leavingMemberCost` | حصة المنسحب قبل الخروج (مشترك + فردي) |
| `remainingShares` | الحصص الجديدة للباقين |
| `remainingSharedTotal` | المشترك المعاد توزيعه |
| `unassignedSharedTotal` | غير موزَّع (عند خروج آخر عضو) |
| `windowOpen` | هل الانسحاب داخل نافذة السياسة |
| `policyVersion` / `reasonKey` | نسخة السياسة وسببها المعروض |

- **بنود المنسحب الفردية تسقط** من النسخة الجديدة.
- **خروج آخر عضو** ⇒ لا توزيع على أحد، ويُعرض `groupEmpty` بصدق.
- **إضافة عضو** ⇒ إعادة حساب على المجموعة الجديدة.
- **لا يُعدَّل شيء تلقائياً في الميزانية المعتمدة:** إعادة الإصدار **إجراء صريح** (`reissueVersion`) يُصدر نسخة جديدة ويصفّر الموافقات.

### 5.1 قيد known: الانسحاب في نمط `custom`

الحصص المخصصة **لا تُعاد تلقائياً** بعد تغيّر الأعضاء ⇒ المحرك يرفض بـ`CUSTOM_SUM_MISMATCH`. الواجهة تعرض السبب وزر **إعادة إصدار النسخة** (الذي يحوّل النمط إلى `equal` عند إعادة الإصدار من `custom`). **الحل الكامل (إعادة إعلان الحصص) بند مفتوح** يحتاج قراراً بشرياً في طريقة إعادة التوزيع.

## 6) النسخ والموافقات

```
v1 (draft) → بنود → موافقات الأعضاء → adopted → agreed
                 ↓ أي تعديل
              approvals = [] · version → draft · group agreed → planning
                 ↓ إعادة إصدار
              v2 (draft) → موافقات جديدة → adopted
```

| القاعدة | التفصيل |
|---------|---------|
| ترقيم | `bumpVersion(max)` — يبدأ من 1 ويزيد |
| الموافقة | لكل عضو نشط على النسخة الحالية |
| الاعتماد | `allApproved(required, approvals)` — **الإجماع إلزامي** |
| التصديق | `agreementComplete(required, acknowledgements)` لكل الأعضاء |
| التصحيح | أي إضافة/حذف بند أو تغيير نمط ⇒ تصفير الموافقات |
| السجل | الاتفاق **Append-only**؛ الإقرارات تُضاف ولا تُحذف |

**مسار الآلة:** `adoptBudget` يسلك **open → planning → agreed** ولا يقفز حالتين؛ الآلة لم تُوسَّع للالتفاف على ترتيبها (ADR-0049).
