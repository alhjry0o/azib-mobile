# قواعد الوكيل (AGENT_RULES)

وثيقة الحوكمة الملزمة لكل وكيل ذكاء اصطناعي أو مطوّر يعمل على مشروع عازب | AZIB. الغرض: تثبيت السياق ومنع الانحراف العشوائي بين الرسائل والمراحل. عند التعارض بين تعليمات عابرة وهذه الوثيقة، تُعتمد الوثيقة ما لم يُوثَّق تعديلها في `docs/DECISIONS.md`.

## 1. النطاق والأولوية

تسري القواعد على كل مرحلة (P01 إلى P24) وعلى كل ملف في المستودع. ترتيب الأولوية عند التعارض:

1. قواعد HRD (القسم 2).
2. القواعد الـ22 (القسم 3).
3. `PROJECT_CONTEXT.md` والمبادئ الحاكمة فيه.
4. `docs/DECISIONS.md` و`docs/PRODUCT_POLICIES.md`.
5. تعليمات المرحلة الحالية.

مواقع الملفات المرجعية: `docs/AGENT_RULES.md` (هذا الملف)، و`PROJECT_CONTEXT.md` و`DEVELOPMENT_PROGRESS.md` في جذر المستودع.

## 2. القواعد الصارمة HRD

القواعد التسع التالية مأخوذة نصاً من تعليمات المشروع، ولا تُخفَّف:

- **HRD-1:** اقرأ AGENT_RULES.md وPROJECT_CONTEXT.md وDEVELOPMENT_PROGRESS.md إن وُجدت وافحص المستودع قبل أي تعديل.
- **HRD-2:** لا تنشئ تطبيقاً وهمياً: كل زر يعمل أو يفتح شاشة Not Connected صادقة.
- **HRD-3:** لا نصوص عربية Hardcoded (i18n فقط) ولا كسر لـ RTL (Logical Properties).
- **HRD-4:** لا Secrets في التطبيق، لا بيانات بطاقات، لا ادعاء نجاح تكامل لم يُختبر، لا عملية مالية وهمية.
- **HRD-5:** لا تحذف أو تعيد كتابة عمل ناجح دون ضرورة موثقة في docs/DECISIONS.md.
- **HRD-6:** تحقق من توافق كل مكتبة (npx expo install / npx expo-doctor) قبل اعتمادها.
- **HRD-7:** لا بيانات شخصية حقيقية في Seed، وكل بيانات demo تحمل dataOrigin='demo'.
- **HRD-8:** لا تكشف بيانات المستفيدين لغير المخوّلين.
- **HRD-9:** في النهاية شغّل lint وtypecheck وtest وحدّث PROJECT_CONTEXT.md وDEVELOPMENT_PROGRESS.md.

**توضيحات (لا تغيّر النص):**
- يسري HRD-3 على **كود التطبيق** (المكونات والشاشات). الوثائق في `docs/` مكتوبة بالعربية بطبيعتها ولا يشملها المنع.
- HRD-9 مشروطة بوجود أدوات التشغيل. قبل P02 لا يوجد `package.json`، فيُذكر ذلك صراحة في التقرير ولا يُدّعى النجاح. وإذا لم يستطع الوكيل تشغيل الأوامر، فعليه ذكر الأوامر وطلب المخرجات دون ادّعاء نتيجتها.

## 3. القواعد الـ22

كل قاعدة لها معنى عملي ودليل التزام. لا تُعدّ المهمة منتهية إن كُسرت واحدة منها دون استثناء موثّق.

| المعرّف | القاعدة | المعنى العملي | دليل الالتزام |
|---|---|---|---|
| R-01 | لا تطبيق وهمي | كل شاشة أو تدفق إما يعمل فعلياً أو يعرض Not Connected صادقة تشرح ما ينقص | اختبار للمسار أو شاشة Not Connected |
| R-02 | لا الاكتفاء بتصميم الشاشات | الشاشة لا تُعدّ منجزة إلا بمنطقها وحالاتها (تحميل، فراغ، خطأ، صلاحيات) واختباراتها | اختبارات الحالات |
| R-03 | لا أزرار بلا وظيفة | كل عنصر تفاعلي له معالج حقيقي، أو معطّل مع سبب ظاهر ومترجم، أو يفتح Not Connected | مراجعة + اختبار تفاعل |
| R-04 | لا بيانات وهمية كحقيقية | كل بيانات demo تحمل `dataOrigin='demo'` وتُعرض بوسم واضح ولا تختلط بالحقيقية | فحص الحقل + لقطة واجهة |
| R-05 | لا تجاهل حالات الخطأ | كل إدخال أو استدعاء خارجي له معالجة خطأ ورسالة مترجمة وخيار إعادة المحاولة عند المناسب | اختبارات مسارات الفشل |
| R-06 | لا مفاتيح سرية | لا أسرار في الكود أو المستودع أو حزمة التطبيق. الأسرار في الخادم أو أسرار CI فقط. المفاتيح العامة المصمَّمة للنشر (مثل anon key) ليست أسراراً لكنها ليست حماية؛ الحماية بالصلاحيات على الخادم | فحص أسرار في CI (P22) |
| R-07 | لا تكرار كود | يُستخرج المتكرر إلى وحدة مشتركة بدل النسخ | مراجعة الكود |
| R-08 | لا مكتبة دون تحقق | قبل الاعتماد: `npx expo install` و`npx expo-doctor` ومراجعة الترخيص والصيانة، ثم تسجيلها في PROJECT_CONTEXT | مخرجات الأوامر في التقرير |
| R-09 | لا كسر RTL | Logical Properties (start/end) بدل left/right، واختبار الاتجاهين، وانعكاس الأيقونات الاتجاهية | اختبار RTL/LTR |
| R-10 | لا نصوص عربية داخل المكونات | مفاتيح i18n فقط، والنصوص في ملفات الترجمة | فحص آلي يُقرَّر في P02/P03 |
| R-11 | لا ملف واحد ضخم | يُقسَّم الملف حين يتولى أكثر من مسؤولية واحدة | مراجعة الكود |
| R-12 | لا حذف دون سبب | حذف أو إعادة كتابة عمل ناجح يتطلب مدخلاً موثقاً في DECISIONS.md | وجود ADR |
| R-13 | لا تغيير معماري دون توثيق | أي تغيير في المكدس أو البنية أو النموذج المالي أو الأمني يسبقه ADR | وجود ADR |
| R-14 | لا API غير موجود | لا تستدعِ دالة أو مكتبة أو endpoint لم يُتحقق من وجوده في التوثيق أو الأنواع. وإن لم تعرف فاطلب المصدر | typecheck + مرجع التوثيق |
| R-15 | لا ادعاء نجاح تكامل غير مختبر | لا يُعلن نجاح إلا مع مخرجات اختبار فعلية. بلا وصول للتشغيل: اذكر الأوامر واطلب المخرجات | مخرجات مرفقة |
| R-16 | لا خدمات مدفوعة إلزامية | لا يتوقف التشغيل الأساسي على خدمة مدفوعة. أي خدمة مدفوعة اختيارية خلف Provider ببديل مجاني أو Not Connected | ADR لكل خدمة خارجية |
| R-17 | لا بيانات بطاقات | لا جمع ولا تخزين ولا تسجيل (log) لأرقام البطاقات أو CVV بأي شكل | مراجعة + فحص السجلات |
| R-18 | لا اعتماد Demo على خدمات غير متاحة | وضع demo يعمل محلياً دون حسابات أو شبكة خارجية | تشغيل demo دون اتصال |
| R-19 | لا تجاوز صلاحيات | تُفرض الصلاحيات على الخادم (RLS) لا بالواجهة فقط، وبأقل صلاحية ممكنة | اختبارات pgTAP (P18/P21) |
| R-20 | لا كشف بيانات المستفيدين | لا تُكشف لغير المخوّلين، ولا في السجلات أو الإشعارات أو الإحصاءات الصغيرة (POL-08) | اختبارات صلاحيات + مراجعة |
| R-21 | لا نظام دفع تجريبي لتسجيل تبرعات حقيقية | لا يوجد مسار «تجريبي» يسجّل تبرعاً حقيقياً أو يوحي بحدوثه. أي محاكاة تحمل `dataOrigin='demo'` ومعزولة تماماً عن السجلات الحقيقية | مراجعة P09 + اختبار عزل |
| R-22 | لا بيانات شخصية حقيقية في Seed | بيانات اصطناعية فقط بلا أسماء أو أرقام أو وثائق حقيقية، وكلها `dataOrigin='demo'` | فحص ملفات seed |

## 4. حلقة العمل الإلزامية

كل مهمة تمرّ بالخطوات التالية بالترتيب، ولا يُتخطى أي منها:

اقرأ ← خطط ← نفذ ← اختبر ← حدّث الوثائق ← قدّم تقريراً صادقاً بما اكتمل وما لم يكتمل

1. **اقرأ:** قرأ الوكيل هذا الملف و`PROJECT_CONTEXT.md` و`DEVELOPMENT_PROGRESS.md`، وفحص المستودع الفعلي. وإن احتاج ملفاً لا يراه فيطلبه ولا يخمّنه.
2. **خطّط:** يحدد الملفات المتأثرة (جديد/معدّل/محذوف) والمخاطر، ويطرح الأسئلة التي تحتاج قراراً بشرياً قبل البدء.
3. **نفّذ:** ينفذ ضمن نطاق المرحلة فقط. لا يضيف ميزات خارجها، ولا يغيّر المعمارية دون ADR.
4. **اختبر:** يشغّل lint وtypecheck وtest (عند توفرها) ويسجّل المخرجات. إن لم يستطع التشغيل، يعطي الأوامر ويطلب المخرجات.
5. **حدّث الوثائق:** يحدّث `PROJECT_CONTEXT.md` و`DEVELOPMENT_PROGRESS.md` وأي ADR لازم.
6. **قدّم تقريراً صادقاً:** وفق قالب القسم 5.

## 5. قالب التقرير الصادق

كل تقرير نهاية مهمة يحتوي الأقسام التالية، حتى لو كان بعضها فارغاً (يُكتب «لا شيء»):

1. **الملفات:** جديدة / معدّلة / محذوفة.
2. **ما اكتمل:** بدليل (مخرجات أوامر أو اختبارات مرفقة من المالك).
3. **ما لم يكتمل:** بصراحة وسببه.
4. **ما لم يُتحقق منه:** أشياء كُتبت لكن لم تُشغَّل.
5. **قرارات بشرية مطلوبة:** مع إحالة إلى PRODUCT_POLICIES أو DECISIONS.
6. **أوامر التحقق:** التي سيشغلها المالك، دون ادّعاء نتائجها.
7. **المخاطر والخطوة التالية.**

## 6. حالات الميزة الصادقة

لكل ميزة حالة واحدة من الحالات التالية وتُعرض بصدق في الواجهة والوثائق:

| الحالة | المعنى |
|---|---|
| Working | تعمل فعلياً ومختبرة، ومدوَّنة بدليل |
| Not Connected | الواجهة موجودة والخدمة غير متصلة. تعرض شاشة صادقة تشرح ما ينقص ولا تُظهر نجاحاً |
| Demo | تعمل ببيانات `dataOrigin='demo'` موسومة ومعزولة |
| Not Started | غير موجودة |

## 7. حدود قرار الوكيل

لا يقرر الوكيل بنفسه ما يلي، ويطلب فيها قراراً بشرياً موثقاً:

- أي رقم أو عتبة أو مدة في `docs/PRODUCT_POLICIES.md`.
- ترخيص المستودع، والمسائل القانونية والامتثال.
- التغييرات في المبادئ الحاكمة (غير ربحي، Non-Custodial، Advisory، لا تعارف).
- اعتماد خدمة خارجية أو مدفوعة.

وإذا غابت معلومة (محتوى ملف، إصدار، سلوك API)، فعلى الوكيل أن يقول إنها غير معلومة وأن يطلبها.

## 8. أمان الوثائق

هذا المستودع **عام**، وكل ما في `docs/` وجذر المستودع عام. يُمنع فيه:
- الأسرار والمفاتيح الخاصة وكلمات المرور والرموز (tokens).
- البيانات الشخصية الحقيقية لأي شخص، بمن فيهم المستفيدون.
- بيانات البطاقات والحسابات المصرفية الحقيقية.
- تفاصيل استغلال ثغرات تؤثر على نظام حي.

أمثلة الوثائق تستخدم بيانات اصطناعية فقط.

## 9. تعديل هذه الوثيقة

أي تعديل على هذا الملف يتطلب ADR في `docs/DECISIONS.md` يشرح السبب. ولا يجوز تخفيف HRD أو القواعد الـ22 دون قرار بشري صريح من المالك.
