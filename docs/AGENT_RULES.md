# AGENT_RULES — قواعد الحوكمة الإلزامية لمشروع «عازب | AZIB»

> **هذا الملف عام المستودع (public repository).** لا تكتب فيه أي سر أو مفتاح أو بيانات شخصية حقيقية.
> أي تعديل على هذا الملف يتطلب موافقة صريحة من مالك المشروع، ويُوثَّق في `docs/DECISIONS.md`.

---

## 0) تعريف HRD (Human Requirements Document)

**المشروع:** عازب | AZIB — منصة اجتماعية **غير ربحية** لتيسير الزواج في السوق الأول صنعاء/اليمن، بعملة `YER`، ولغة افتراضية `ar` مع RTL، وبنية متعددة اللغات.

**نطاق الخدمات:** مساعدات مالية منضبطة، أعراس جماعية، شركاء بخصومات، سوق خير للتبرعات العينية، وظائف، متطوعون، توعية.

**المبادئ الحاكمة (غير قابلة للتفاوض):**
- غير ربحي: **لا عمولات، لا اشتراكات، لا رسوم على المستفيدين**.
- **لا خدمات تعارف**، ولا ملفات عامة للأفراد، ولا بحث عن شريك داخل التطبيق.
- **اختيار الزوج مسؤولية الأسر**، والمنصة لا تتوسط في الاختيار.
- الخصوصية والشفافية أساسان لكل شاشة ولكل جدول بيانات.
- **لا مساعدة مالية دون تحقق بشري** من الأهلية.
- **Non-Custodial**: التطبيق لا يحتفظ بأموال، لا محفظة، لا Escrow، لا تحويل داخلي.
- القرار النهائي في الأهلية والمساعدة لمراجعة بشرية، والتقييم الآلي **Advisory فقط** ولا يحجب/يمنح حقاً بذاته.

**المكدس المعتمد:**
- Expo + React Native + TypeScript (strict) + Expo Router.
- Zustand (حالة العميل) + TanStack Query (حالة الخادم).
- React Hook Form + Zod للتحقق من النماذج.
- i18next للترجمة.
- Reanimated + Gesture Handler للحركة.
- Supabase خلف **Provider Abstraction** (لا استخدام مباشر في المكونات).
- Jest + RNTL للاختبارات، Playwright (Web) للـ E2E، pgTAP لقاعدة البيانات.
- GitHub Actions للـ CI. مدير الحزم: **npm**.

**الأدوار (Roles):**
`guest`, `member`, `applicant`, `donor`, `partner_owner`, `ambassador`, `volunteer`, `reviewer`, `moderator`, `partner_verifier`, `finance_officer`, `content_editor`, `admin`, `auditor`.

**الهوية البصرية:**
- Royal Black `#09080F`
- Royal Purple `#7136C9` / Electric `#9B5CFF`
- Mustard `#D9A928` / Soft Gold `#F0CA68`
- أسلوب Premium Dark، عنصر بصري مركزي: «القمريات» (Qamariya) وحلقتان متداخلتان كرمز للزواج.

**المراحل (24 مرحلة):** P01 Governance · P02 Init · P03 Core Platform · P04 Design System · P05 Shell+Onboarding · P06 Auth/Profile/Settings/Legal · P07 Home · P08 Assistance+Eligibility · P09 Financial Architecture · P10 Group Weddings · P11 Partners+Ambassadors · P12 Souk · P13 Jobs+Volunteers · P14 Calculator+Guide · P15 Education+Charter+Impact · P16 Notifications+Search · P17 Staff Console · P18 Supabase · P19 Security · P20 Offline/Perf/A11y · P21 Testing · P22 GitHub Actions · P23 Docs · P24 Final Integration.

**القواعد الصارمة العليا (Hard Rules) من HRD:**
1. اقرأ `AGENT_RULES.md` و`PROJECT_CONTEXT.md` و`DEVELOPMENT_PROGRESS.md` وافحص المستودع قبل أي تعديل.
2. لا تنشئ تطبيقاً وهمياً: كل زر يعمل فعلياً أو يفتح شاشة **Not Connected** صادقة.
3. لا نصوص عربية Hardcoded (i18n فقط)، ولا كسر لـ RTL (Logical Properties فقط).
4. لا أسرار في التطبيق، لا بيانات بطاقات، لا ادعاء نجاح تكامل لم يُختبر، لا عملية مالية وهمية.
5. لا تحذف أو تعيد كتابة عمل ناجح دون ضرورة موثقة في `docs/DECISIONS.md`.
6. تحقّق من توافق كل مكتبة (`npx expo install` / `npx expo-doctor`) قبل اعتمادها.
7. لا بيانات شخصية حقيقية في Seed، وكل بيانات Demo تحمل `dataOrigin='demo'`.
8. لا تكشف بيانات المستفيدين لغير المخوّلين.
9. في نهاية كل مرحلة: شغّل `lint` و`typecheck` و`test` وحدّث `PROJECT_CONTEXT.md` و`DEVELOPMENT_PROGRESS.md`.

## 1) القواعد الـ22

| # | القاعدة | التطبيق العملي |
|---|---------|-----------------|
| 1 | **لا تطبيق وهمي** | كل شاشة مرتبطة بمنطق حقيقي أو بحالة `Not Connected` صادقة وواضحة للمستخدم. |
| 2 | **لا الاكتفاء بتصميم الشاشات** | التسليم يتضمن بيانات، تحقق، حالات تحميل/خطأ/فراغ، واختبارات — لا Mockup فقط. |
| 3 | **لا أزرار بلا وظيفة** | كل زر إما ينفّذ عملاً، أو يعطّل نفسه بحالة `disabled` مع سبب، أو يقود لشاشة `Not Connected`. |
| 4 | **لا بيانات وهمية كحقيقية** | أي Seed/Demo يحمل `dataOrigin='demo'` ويظهر عليه وسم Demo في الواجهة. |
| 5 | **لا تجاهل حالات الخطأ** | كل نداء شبكة/IO له 3 حالات صريحة على الأقل: `loading` / `error` / `empty` بجانب `success`. |
| 6 | **لا مفاتيح سرية** | لا `service_role`، لا مفاتيح دفع، لا Tokens في المستودع. الأسرار في `.env.local` + `.gitignore` + GitHub Secrets. |
| 7 | **لا تكرار كود** | قبل كتابة أي منطق، ابحث عن مشابه. النسخ المتكرر ≥ 3 مرات يُستخرج لمكوّن/دالة مشتركة. |
| 8 | **لا مكتبة دون تحقق** | كل مكتبة جديدة تُمرَّر عبر `npx expo install` و`npx expo-doctor`، وتُسجَّل في `docs/DECISIONS.md`. |
| 9 | **لا كسر RTL** | استخدام `start/end` و`marginStart` و`paddingEnd` فقط. لا `left/right` لتخطيط منطقي. تُختبر الواجهة بـ `ar` أولاً. |
| 10 | **لا نصوص عربية داخل المكونات** | كل نص عبر `t('...')` من i18next، وملفات اللغة هي الوحيدة التي تحتوي النصوص. |
| 11 | **لا ملف واحد ضخم** | حد عملي: ~200 سطر للمكوّن، ~300 سطر للـ module. التجاوز يستلزم تفكيكاً أو تبريراً في PR. |
| 12 | **لا حذف دون سبب** | أي حذف/إعادة كتابة لعمل سابق يُوثَّق في `docs/DECISIONS.md` مع السبب والبديل. |
| 13 | **لا تغيير معماري دون توثيق** | أي تغيير في المكدس، الطبقات، حدود الوحدات، أو نموذج البيانات = ADR جديد بموافقة. |
| 14 | **لا API غير موجود** | لا تُستدعى واجهات غير موثقة أو غير مختبرة. الشرط: وجود في الـ Provider + اختبار أو ردّ موثَّق. |
| 15 | **لا ادعاء نجاح تكامل غير مختبر** | لا يُقال «يعمل» إلا بعد تشغيل فعلي على بيئة محددة مع إشارة لطريقة التحقق. |
| 16 | **لا خدمات مدفوعة إلزامية** | المسار الأساسي للمشروع يعمل على الطبقات المجانية/المحلية فقط. أي خدمة مدفوعة اختيارية ومُعلنة. |
| 17 | **لا بيانات بطاقات** | لا PCI scope: لا `card number`، لا `CVV`، لا `IBAN` داخل التطبيق. الدفع يتم خارجياً عبر مزوّد مرخّص عند الحاجة. |
| 18 | **لا اعتماد Demo على خدمات غير متاحة** | أي Demo يجب أن يعمل دون شبكة (Local Fixtures) أو يعلن بوضوح أنه يحتاج اتصالاً. |
| 19 | **لا تجاوز صلاحيات** | كل مسار محمي يمر على فحص دور صريح في الواجهة **و** RLS في القاعدة. الواجهة وحدها ليست ضابط أمان. |
| 20 | **لا كشف بيانات المستفيدين** | بيانات المستفيدين PII محصورة بأدوار: `reviewer`, `moderator`, `finance_officer`, `admin`, `auditor`. الحد الأدنى من الظهور مبدأ افتراضي. |
| 21 | **لا نظام دفع تجريبي لتسجيل تبرعات حقيقية** | التبرعات الحقيقية تُسجَّل فقط عبر مزوّد مرخّص مُتحقَّق منه. لا «محاكاة دفع» تُنتج إيصالاً حقيقياً. |
| 22 | **لا بيانات شخصية حقيقية في Seed** | كل Seed بأسماء/هواتف/عناوين وهمية متولَّدة، مع `dataOrigin='demo'`، ولا تُنسخ من بيانات إنتاج أبداً. |

## 2) حلقة العمل الإلزامية لكل مرحلة

```
اقرأ  →  خطّط  →  نفّذ  →  اختبر  →  حدّث الوثائق  →  قدّم تقريراً صادقاً
```

تفصيلها:

1. **اقرأ:** `AGENT_RULES.md` + `PROJECT_CONTEXT.md` + `DEVELOPMENT_PROGRESS.md` + `docs/DECISIONS.md` + بنية المستودع الحالية، قبل أي تعديل.
2. **خطّط:** اذكر الملفات التي ستُنشأ/تُعدَّل، والمخاطر، وما يحتاج قراراً بشرياً.
3. **نفّذ:** بأصغر تغيير كافٍ، وبدون كسر عمل ناجح، وبدون كود زائد غير مطلوب في المرحلة.
4. **اختبر:** `npm run lint` + `npm run typecheck` + `npm test` (وحيث ينطبق: `expo-doctor`, Playwright, pgTAP).
5. **حدّث الوثائق:** `PROJECT_CONTEXT.md` + `DEVELOPMENT_PROGRESS.md` + `docs/DECISIONS.md` عند الحاجة.
6. **قدّم تقريراً صادقاً:** ما اكتمل، ما لم يكتمل، ما لم يُختبر، وما يحتاج قراراً بشرياً. **لا ادعاء نجاح.**

## 3) بيئة التنفيذ (Agent Reality)

- الوكيل قد لا يملك وصولاً للمستودع أو لأوامر الشل.
- في هذه الحالة: المستخدم هو حلقة الوصل، والوكيل **لا يفترض** نتيجة أي أمر.
- عند الحاجة لملف غير مُرسَل: **يُطلب بالاسم**، ولا يُخمَّن محتواه.
- عند عدم التأكد من واجهة API: يُذكر صراحةً، ويُطلب تحقق من المستخدم/مرجع رسمي.
