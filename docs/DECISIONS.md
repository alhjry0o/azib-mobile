## ADR-0001 — استخدام npm بدل pnpm
- **التاريخ:** 2026-11-08 · **الحالة:** Accepted
- **السياق:** Expo مساره المدعوم والأكثر اختباراً مع npm؛ pnpm يضيف طبقة تعقيد قد تتعارض مع إضافات Expo.
- **القرار:** npm مدير الحزم الوحيد في المستودع وCI. لا `pnpm-lock.yaml` ولا `yarn.lock` ولا `bun.lockb`.
- **البدائل:** pnpm (أسرع لكن دعم Expo أقل اختباراً)؛ yarn (لم يُطلب).
- **التبعات:** + متوافق مع `npx expo install`. − مساحة أكبر لـ`node_modules`.
- **المراجعة:** دعم رسمي مُختبَر لـpnpm.
- **المراجع:** `AGENT_RULES.md`، وثائق Expo.

## ADR-0002 — Zustand (حالة العميل) + TanStack Query (حالة الخادم)
- **التاريخ:** 2026-11-08 · **الحالة:** Accepted
- **السياق:** فصل حالة الواجهة قصيرة العمر عن حالة الخادم.
- **القرار:** Zustand للواجهة فقط؛ Query لكل قراءة/كتابة على الخادم. لا بيانات خادم في Zustand.
- **البدائل:** Redux Toolkit (أثقل)؛ Context عام (لا يصلح لحالة خادم).
- **التبعات:** + فصل مسؤوليات. − منحنى تعلّم لمفاتيح Query وسياسات `staleTime`.
- **المراجعة:** أخطاء متكررة من تكرار المصدر.
- **تحديث P05:** الجلسة في Query بمفتاح يحوي AppMode.
- **تحديث P06:** ستة متاجر عميل خالصة؛ الصورة في Query cache (ADR-0020).
- **تحديث P07:** تخصيص الرئيسية (ترتيب/إظهار) تفضيل عميل في `settings.store`؛ كل بيانات الأقسام في Query باستعلام مستقل لكل قسم.

## ADR-0005 — نموذج Non-Custodial

## ADR-0017 — TokenVault: SecureStore على الجهاز، ذاكرة على الويب
- **التاريخ:** 2026-11-16 · **الحالة:** Accepted

## ADR-0021 — حذف بفترة تأكيد + تصدير JSON + سجل وثائق قانونية بنسخ

## ADR-0022 — عزل واجهات Expo الأصلية في وحدات حدودية
- **التاريخ:** 2026-11-16 · **الحالة:** Accepted
- **السياق:** فشل افتراضان لواجهات Expo (manipulator الكائنية غير موجودة؛ file-system تُصدّر الصنفية والكلاسيكية في `/legacy`)، والوكيل لا يقرأ `node_modules`.
- **القرار:** كل استدعاء لحزمة أصلية في وحدة حدودية واحدة: `token-vault` · `image-pipeline` · `biometric` · `export-file`. الإصلاح ينحصر في الوحدة + mock اختبارها. تحقق مقترح: `npm ls` / `expo install --check` / قراءة `.d.ts`. mocks الحزم الجديدة محلية إن كان `jest.setup.ts` معدَّلاً خارج الجلسة.
- **البدائل:** استدعاء مباشر من الشاشات؛ الاعتماد على الذاكرة؛ تثبيت إصدارات أقدم.
- **التبعات:** + كلفة الإصلاح انحصرَت مرتين. − طبقة تغليف صغيرة؛ لا يُلغي الحاجة للتحقق.
- **المراجعة:** وصول موثوق لملفات الأنواع أو توحيد Expo لواجهاتها.

## ADR-0023 — HomeConfig قابل للتبديل + تخصيص محلي فعلي
- **التاريخ:** 2026-11-16 · **الحالة:** Accepted
- **السياق:** HRD يطلب رئيسية قائمة على تكوين قابل للتخصيص، ومصدراً قابلاً للتبديل (Mock الآن، Settings لاحقاً). لا عقد لخادم يخدم تكوين الرئيسية، ومزامنة التكوين per-user عبر `SettingsRepository` تحتاج سياسة مفاتيح لم تُقرَّر.
- **القرار:**
  - واجهة `HomeConfigSource { id, load(): Promise<Result<HomeConfig>> }` + تنفيذ Mock + سجل وحدة بـ`get/set/resetHomeConfigSource` — **الاستبدال لا يمسّ المستهلكين**.
  - `DEFAULT_HOME_CONFIG` يرتّب الأقسام الثمانية بترتيب مستقر؛ دوال نقية: `normalizeOrder` (إسقاط المجهول/المكرر وإلحاق الناقص)، `hiddenFromMap` (false الصريحة فقط)، `moveInList`.
  - **التخصيص فعلي اليوم** عبر `settings.store`: `homeSectionOrder` · `homeSectionVisibility` · `homeQuickActionVisibility` (محفوظة على الجهاز، تفضيل عميل per ADR-0002).
  - `sections/registry.ts` يرشّح الترتيب إلى الأقسام المنفَّذة فقط؛ ورقة التخصيص لا تعرض ما لا وجود له.
  - إضافة قسم جديد = تسجيله في الـregistry؛ يظهر ويصبح قابلاً للتخصيص تلقائياً.
- **البدائل المدروسة:** ترتيب مثبّت في الكود (لا تخصيص)؛ التكوين في Query فقط (يضيع بإعادة التشغيل)؛ `SettingsRepository` الآن (سياسة مفاتيح/مزامنة غير معتمدة)؛ متجر جديد منفصل (تعقيد بلا داعٍ).
- **التبعات:**
  - + تبديل المصدر بلا تعديل المستهلكين، وتخصيص يصمد أمام إعادة التشغيل.
  - + المعرّفات المجهولة لا تكسر العرض.
  - − الترتيب مخزَّن كـ`string[]` ويُتحقق منه في طبقة التكوين لا في المتجر.
  - − لا مزامنة عبر الأجهزة حتى يُربط المصدر بـSettings (PROJECT_CONTEXT §8 #38).
- **معايير المراجعة:** تنفيذ مصدر Settings-backed (P18+)، أو تجاوز عدد الأقسام ثمانية.
- **المراجع:** `features/home/config/*`, `hooks/use-home-config.ts`, `sections/registry.ts`, `stores/settings.store.ts`.

## ADR-0024 — بوابة موافقة النشر fail-closed + تعقيم بطاقات الدعم
- **التاريخ:** 2026-11-16 · **الحالة:** Accepted
- **السياق:** HRD يشترط نشر حالات الدعم وقصص النجاح **بموافقة سارية**، وبلا أي بيانات تعريفية. عقدا `Application` و`ContentRecord` **لا يحويان أي حقل موافقة أو نشر**، والقاعدة `§1 #20` تمنع كشف بيانات المستفيدين، و`§1 #14` تمنع اختراع واجهات.
- **القرار:**
  - `PublicationConsent { subjectId, grantedAt, revokedAt|null }` كمصدر الحقيقة الوحيد للنشر.
  - `isConsentActive` **fail-closed**: يرفض المفقود، والتاريخ الفاسد، والمنح المستقبلي، والسحب الماضي، **والسحب غير القابل للتحليل**.
  - `indexConsents` يعتمد الأحدث لكل subject.
  - `toPublicSupportCase` يشترط حالة قابلة للنشر (`approved|disbursed`) **و** موافقة سارية، ثم يُسقط **فقط**: `id` (مبهم) · `categoryKey` · `governorateKey` · `dataOrigin`. **ممنوع دائماً:** `applicantId` · `programId` · `notes` · `reviewerNote` · `requestedAmount` (ولا مقرّباً) · أي بيانات تواصل.
  - `selectPublicStories` يشترط موافقة لكل سجل؛ **موافقة الحساب `storiesConsent` ليست بديلاً** وتُعرض كملاحظة فقط.
  -因为没有 مصدر موافقات في العقود، القسمان يعرضان **حالة فارغة صادقة + السبب + إجراء حقيقي**، والمنطق مُسلَّم ومُختبَر الآن وجاهز لـP08/P15.
- **البدائل المدروسة:** العرض بلا موافقة (يخالف #20)؛ استخدام موافقة الحساب لكل القصص (موضوع خاطئ)؛ اختراع حقول في العقود (يكسر Contract Tests ويخالف #14)؛ إخفاء القسمين كلياً (يفقد السبب المعلن).
- **التبعات:**
  - + خصوصية مضمونة بالبناء، ومنطق مُختبَر قبل وجود البيانات.
  - + جاهزية فورية عند إضافة حقول الموافقة.
  - − القسمان فارغان دائماً حتى P08/P15/P18 (PROJECT_CONTEXT §8 #39).
  - − معرّف الحالة المبهم يبقى ظاهراً؛ لا مسار عام يحلّه إلى شخص.
- **معايير المراجعة:** إضافة حقول موافقة النشر في P08/P15، أو تغيّر سياسة النشر بقرار المالك (`PRODUCT_POLICIES #10` المقترح).
- **المراجع:** `features/home/consent-gate.ts`, `anonymize.ts`, `success-stories.ts`, `sections/SupportCasesSection.tsx`, `sections/SuccessStoriesSection.tsx`.

## ADR-0025 — إخفاء الأعداد الصغيرة **والمبالغ معها**
- **التاريخ:** 2026-11-16 · **الحالة:** Accepted
- **السياق:** `PRODUCT_POLICIES #8` غير معتمد (قيمة مؤقتة < 10). الرئيسية تعرض إحصاءات مجتمعية، ومجموع مبالغ مجموعة صغيرة يكشفها حتى لو حُجب عددها.
- **القرار:**
  - `SMALL_NUMBER_THRESHOLD = 10` مُصدَّر وموسوم `PENDING_POLICY` في الكود والواجهة.
  - `suppressSmallNumber` يحجب أي عدد دون الحد أو غير منتهٍ.
  - `buildStatCell` **يحجب المبلغ تلقائياً كلما حُجب العدد**.
  - تُحتسب السجلات `confirmed` فقط.
  - الواجهة تعرض دائماً ملاحظة «الحد مؤقت وبانتظار اعتماد الجهة المالكة».
- **البدائل المدروسة:** حجب العدد وحده (تسريب عبر المجموع)؛ تقريب/تجميع المبالغ (يبقى كاشفاً عند n صغير)؛ إخفاء القسم كله (يفقد شرح القاعدة)؛ انتظار الاعتماد (يحجب P07).
- **التبعات:**
  - + خصوصية محافظة وقاعدة مرئية للمستخدم.
  - + وحدة واحدة قابلة لإعادة الاستخدام في P15/P17.
  - − بحجم البيانات التجريبي الحالي كل الخلايا محجوبة (موثّق ومقصود).
- **معايير المراجعة:** اعتماد المالك للحد ⇒ تحديث الثابت والملاحظة؛ أو تغيّر شكل العرض (نطاقات بدل حجب) بقرار بشري.
- **المراجع:** `features/home/stats-privacy.ts`, `sections/CommunityStatsSection.tsx`, `docs/PRODUCT_POLICIES.md §8`.

## ADR-0026 — فصل Demo/Real صارم في الإحصاءات
- **التاريخ:** 2026-11-16 · **الحالة:** Accepted
- **السياق:** القاعدة `§1 #4` تمنع تقديم بيانات تجريبية كحقيقية. كل المستودعات demo حتى P18، وأي تجميع مختلط قد يعرض رقماً تجريبياً كإنجاز فعلي دون قصد.
- **القرار:**
  - `computeCommunityStats` يقسّم التبرعات والصرف والمستفيدين حسب `dataOrigin` إلى **دلويين منفصلين**: `demo` و`real`.
  - **الواجهة تعرض دلو demo حصراً**، مع شارة demo ونص صريح بأن لا أرقام حقيقية تُعرض هنا.
  - دلو `real` يُحسب ولا يُrender إطلاقاً قبل P18.
  - حالة فارغة صادقة إذا كان مجموع السجلات صفراً.
  - لا يوجد أي تجميع يخلط الأصلين.
- **البدائل المدروسة:** دلو واحد بعلم demo (خطر الخلط)؛ إخفاء الإحصاءات حتى وجود بيانات حقيقية (يحجب الميزة)؛ وسم كل صف على حدة (يسمح بجمع مختلط).
- **التبعات:**
  - + استحالة تقديم demo كحقيقي بالبناء.
  - + جاهزية P18: يُقلب العرض إلى دلو real مع إبقاء demo خلف وضع المطور.
  - − دلو real كود غير معروض حتى P18 (مبرَّر: هو حدّ التقسيم المُختبَر).
- **معايير المراجعة:** P18 عند وجود بيانات حقيقية ⇒ عرض دلو real، وسياسة عرض demo في الإنتاج.
- **المراجع:** `features/home/stats-privacy.ts`, `sections/CommunityStatsSection.tsx`, `AGENT_RULES §1 #4`.
